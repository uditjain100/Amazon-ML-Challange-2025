# Smart Product Pricing Dataset

This directory stores the canonical tabular assets for the Amazon ML Challenge 2025 Smart Product Pricing task, together with sample submissions and archived prediction runs.

## Contents
- `train.csv` labelled training set (75,000 rows). Use for full-model fitting, cross-validation, and feature exploration.
- `test.csv` unlabeled evaluation set (75,000 rows). Must be scored to create final submissions.
- `sample_test.csv` schema sanity-check file (100 rows). Useful when prototyping loaders or notebooks.
- `sample_test_out.csv` reference output illustrating the required submission format (matching column names, order, and quoting rules).
- `test_out.csv` current working submission generated by the most recent pipeline execution.
- `test_out_1.csv` … `test_out_9.csv` historical prediction files retained for comparison or rollback.
- `.DS_Store` macOS metadata file; safe to ignore but keep out of submissions.
- Additional artefacts such as `cv_metrics_log.csv`, `final_model.pkl`, feature cache files, or image download manifests may appear when running advanced scripts (e.g., `src/clean.py` or the `src/spp_*.py` series).

## Schema

The training and test files share the same feature columns. Only `train.csv` includes the `price` target.

| Column           | Type     | Notes                                                                 |
|------------------|----------|-----------------------------------------------------------------------|
| `sample_id`      | string   | Unique identifier; preserve ordering when joining predictions.        |
| `catalog_content`| string   | Concatenated title, description, and Item Pack Quantity text.         |
| `image_link`     | string   | URL to the product image; optional for text-only models.              |
| `price`          | float    | Target variable present only in `train.csv`; must stay positive.      |

All text is UTF-8 encoded. Missing values appear as blank strings and should be handled during preprocessing. Numerical features derived from text (pack size, net weight, etc.) need to be engineered inside your pipeline.

### Column Characteristics
- `sample_id` is unique across both train and test. Treat it as a categorical identifier, not a numeric value. You can safely join predictions using this column without resorting to positional merges.
- `catalog_content` concatenates title, bullets, ingredients, pack size, and occasionally marketing messages. Expect mixed casing, Unicode punctuation, numeric patterns (e.g., "Pack of 4"), and unit descriptors. Average length is ~600 characters with occasional outliers exceeding 2,000 characters.
- `image_link` points to publicly accessible product imagery, mostly Amazon CDN URLs. About 2–3% of entries may be missing, malformed, or return HTTP errors. Cache downloads locally to avoid throttling.
- `price` (train only) is a strictly positive float with a long tail. Investigate log transforms or winsorisation to stabilise training for sensitive learners.

## Usage Notes
- Always read files with explicit dtypes, for example:  
  ```python
  pd.read_csv("dataset/train.csv", dtype={"sample_id": str})
  ```
- When producing submissions, ensure `test_out.csv` exactly mirrors `sample_test_out.csv` in column names, order, quoting, and number of rows (`len(test.csv)`).
- Maintain deterministic sorting by `sample_id` to avoid leaderboard discrepancies.
- Advanced pipelines (e.g., `clean.py`) can cache feature matrices or models back into this folder. Commit only the lightweight CSV outputs unless larger artefacts are intentionally shared.
- If you regenerate the dataset from upstream sources, keep the same file names so that existing scripts continue to work without modification.
- Track derived artefacts (feature matrices, embeddings, cached predictions) under subdirectories such as `dataset/cache/` to avoid cluttering the top-level folder.
- When running inside notebooks, set the working directory explicitly (e.g., `os.chdir(Path(__file__).resolve().parent)`) to ensure relative paths remain valid across environments.

## Recommended Workflows
- **Cross-validation:** Stratify or group splits by `catalog_content` length, price quantiles, or `sample_id` hash when experimenting with leakage-sensitive models. Store results in `cv_metrics_log.csv` with timestamps.
- **Feature Engineering:** Use regex or NLP tokenisation to extract pack counts, weight/volume, flavour descriptors, and health claims. Persist intermediate features as `.parquet` or `.npz` files inside `dataset/cache/` for reproducibility.
- **Image Augmentation:** Download images via `src/utils.py` into `dataset/images/`. Save a manifest (CSV mapping `sample_id` to file path) for synchronous training pipelines.
- **Submission Verification:** Before uploading, diff your `test_out.csv` against `sample_test_out.csv` headers and run:  
  ```python
  import pandas as pd
  sub = pd.read_csv("dataset/test_out.csv")
  ref = pd.read_csv("dataset/test.csv", usecols=["sample_id"])
  assert len(sub) == len(ref)
  assert set(sub.columns) == {"sample_id", "price"}
  assert sub["price"].gt(0).all()
  ```

## Data Quality Checks
- Confirm that `sample_id` has no duplicates (`df["sample_id"].duplicated().any()`).
- Detect blank `catalog_content` entries (rare) and decide on fallback logic (e.g., default embedding or median price).
- Monitor price outliers by inspecting the 1st/99th percentiles. Clip or log-transform as needed to stabilise training.
- Validate that `image_link` domains are expected (mostly `m.media-amazon.com`) and flag unknown hosts for manual inspection.
- Ensure your preprocessing handles special characters such as registered trademark symbols or fractions; they appear in `catalog_content`.

## Storage and Version Control
- Large CSVs should generally be tracked with Git LFS or excluded from commits depending on your collaboration model. Coordinate with your team before pushing updates.
- Clean old `test_out_*.csv` files periodically to keep the repository lean. Retain the most relevant milestones in `student_resource/Submissions/`.
- When sharing the dataset externally, package it with this README to preserve context and usage guidelines.
